### 1. QA · 작성 중 새로고침 (복구 기능 구현 전)

요구사항: **최종 저장 전에 새로고침해도 작성하던 값과 단계를 유지한다.**

**대표 과업: 원어민 화상수업 예약** (최종 저장 = '예약 신청하기' 성공)
- 시작 조건: 새 탭, Chrome, 예약 내역과 임시값이 없는 상태. 이름 '홍세환', 날짜 2026-12-20, 시간 '오후 8:00', 주제 '상황별 회화', 전할 말 20자, 피드백 이메일 받기 선택 후 'p01@example.com' 입력
- 행동: '예약 신청하기'를 누르기 전에 브라우저 새로고침
- 기대 결과: 작성하던 이름·날짜·시간·주제·전할 말·이메일이 남아 이어서 신청 가능
- 실제 결과: 이름·날짜·시간·전할 말이 빈칸, 주제는 기본값 '자유 대화', 피드백 체크가 풀리고 이메일 칸이 숨겨짐, 글자 수는 '0 / 200자'
- 사용자 영향(예상): 여섯 항목을 다시 입력해야 하고, 특히 직접 고민해서 쓴 '전할 말'을 다시 써야 함. 실제 재입력·도움 요청은 사용자 테스트에서 기록
- 재확인 기준: 수정 뒤 같은 조건에서 값과 선택 상태, 이메일 칸이 돌아오는지 확인

**다른 경로: 학습 설정** (최종 저장 = '설정 완료하기')
- 시작 조건: 위와 같은 새 탭. 카메라 동의 -> 안내 창에서 설정 시작 -> 닉네임 '두근이' -> 2단계에서 단어 10개, 문장 포함, 문장 3개 선택
- 행동: '내용 확인하기'를 누르기 전에 새로고침
- 기대 결과: 2단계 화면과 닉네임/선택 조건이 그대로 보임
- 실제 결과: 카메라 동의가 풀리고 학습 설정 영역 전체가 숨겨짐, 닉네임은 빈칸, 단어 수는 기본값 5개, 문장 포함 해제, 문장 수는 2개
- 사용자 영향(예상): 동의 -> 안내 창 -> 닉네임 -> 조건 선택을 처음부터 다시 해야 함
- 재확인 기준: 수정 뒤 같은 조건에서 2단계 화면과 선택값이 돌아오는지 확인

### 2. 작성 상태 복구 구현

- 수정: 입력/선택값과 학습 설정의 1~3단계 위치를 현재 탭의 `sessionStorage`에 임시 보관
- 완료된 예약 목록은 기존처럼 `localStorage`에 유지 (작성 중인 값과 완료된 값은 따로 관리)
- 보관 키: `dugeun-reserve-draft`(예약 폼), `dugeun-flow-draft`(학습 설정)

| 구분 | 예약 폼 | 학습 설정 |
| --- | --- | --- |
| 보관하는 값 | 이름, 날짜, 시간, 주제, 전할 말, 피드백 체크, 이메일 | 닉네임, 단어 수, 문장 포함 여부, 문장 수, 1~3단계 위치 |
| 보관 시점 | 입력·선택할 때마다 (`input`, `change`) | 입력·선택할 때마다, 단계를 이동할 때마다 |
| 보관하지 않는 경우 | 이름·날짜·시간·전할 말이 모두 비어 있을 때 | 닉네임이 비어 있을 때, 완료 화면(4단계) |
| 함께 복구하는 화면 | 글자 수, 선택한 주제, 피드백 이메일 칸 | 카메라 동의 상태, 글자 수, 슬라이더 값, 문장 수 영역, 3단계 요약 |
| 임시값 삭제 | '처음부터 입력하기', '다시 작성', 예약 성공 | '처음부터 입력하기', '다시 설정하기', '설정 완료하기', 카메라 동의 취소 |

- 안내 문장
  - 보관: "작성 내용을 임시 보관했어요."
  - 복구(학습 설정): "작성 내용을 불러왔어요. 2단계(조건)부터 이어서 작성하세요."
  - 복구(예약 폼, 1차 테스트 후 수정): "새로고침 전에 쓰던 예약 내용을 그대로 불러왔어요. 다시 입력하지 않아도 돼요. '처음부터 입력하기'를 눌러도 나의 예약 내역은 지워지지 않아요." 복구하면 이 안내가 보이도록 화면 이동
  - 보관 실패: "작성 내용을 임시 보관하지 못했어요. 새로고침하면 작성 내용이 사라질 수 있어요."
  - 처음부터 입력: "처음부터 입력할 수 있어요."
- 보관값 검사: 읽을 수 없는 값이면 빈 양식에서 시작, 목록에 없는 시간·주제·단어 수는 기본값, 단계 번호가 1~3이 아니면 1단계, 글자 수 제한보다 긴 값은 잘라서 복구
- 저장 중에는 '처음부터 입력하기' 버튼도 '예약 신청하기', '다시 작성'과 함께 비활성화
- 코드 위치(`script.js`): `saveDraft()`, `loadDraft()`, `clearDraft()`(공통), `saveFlowDraft()`, `restoreFlowDraft()`, `saveReserveDraft()`, `restoreReserveDraft()`, 파일 맨 아래에서 복구 실행

- 1차 사용자 테스트 후 수정: 첫 화면에 '원어민 화상수업 예약하기' 링크 추가, 예약 폼 복구 안내 문장과 위치 변경 (근거: [user-test.md](user-test.md) 양식 E-1)

## 12주차 추가한 기능: 재사용 가능한 UI 컴포넌트

### 1. 모달 (공통 모달로 개선 + 예약 상세 보기 추가)
- 사용 목적: 화상통화 시작 전 카메라 활용 안내, 나의 예약 내역의 상세 정보 확인
- 동작 방법
  - '화상통화 설정 시작하기'를 누르면 카메라 활용 안내 모달이 열림
  - '나의 예약 내역'에서 '상세 보기'를 누르면 예약자, 날짜, 시간, 주제, 전할 말, 피드백 이메일을 모달로 보여 줌
  - '닫기' 버튼이나 Esc 키로 닫으면 모달을 열었던 버튼으로 초점이 돌아감
- 재사용 구조: `class="modal"`, `.modal-actions`로 모양을 통일하고 `openModal()`, `closeModal()` 함수와 `data-modal-close` 속성으로 열기/닫기 동작을 공통 처리
- 접근성: `aria-labelledby`로 모달 제목 연결, '상세 보기' 버튼은 "2026-12-01 오후 1:00 예약 상세 보기"처럼 어떤 예약인지 이름에 포함

### 2. 아코디언 (자주 묻는 질문, 새로 추가)
- 사용 목적: 처음 이용하는 학습자가 궁금해할 내용(시작 수준, 수업 시간, 카메라 동의, 복습 방법)을 질문별로 펼쳐 보기
- 동작 방법: 질문을 누르면 답변이 펼쳐지고 '펼치기 +' 문구가 '접기 −'로 바뀌며 배경색이 바뀜, 다시 누르면 접힘
- 재사용 구조: `.accordion-button`이 있는 곳이면 `toggleAccordion()` 함수 하나로 모두 동작 (질문을 추가해도 JavaScript 수정 불필요)
- 접근성: 질문을 `button`으로 만들어 Tab으로 이동하고 Enter/Space로 조작, `aria-expanded`와 `aria-controls`로 열림 상태와 답변 영역 연결

### 3. 탭 (학습 기능, 기존 컴포넌트 개선)
- 사용 목적: 단계별 영어 학습, 원어민 회화 프로그램, 영어 복습 기능을 하나씩 골라 보기
- 개선 전: 페이지의 모든 `.tab`을 한꺼번에 처리해서 탭 묶음이 두 개 이상이면 서로 영향을 줌, 마우스 클릭으로만 전환
- 개선 후: `setupTabs()` 함수가 `.tabs` 묶음마다 따로 동작하도록 변경, <- -> 방향키로 탭 전환 (끝에서 누르면 반대쪽 처음 탭으로 이동)
- 접근성: 선택된 탭만 Tab 키로 들어가고 나머지는 방향키로 이동, `aria-selected`와 밑줄 스타일로 현재 탭 표시

### 확인 순서
1. '학습 기능'의 탭을 Tab으로 선택하고 <- -> 방향키로 전환 -> 선택 표시와 내용이 함께 바뀜
2. 메뉴의 '자주 묻는 질문'에서 질문을 Enter로 펼치고 다시 Enter로 접기
3. 예약을 저장한 뒤 '나의 예약 내역'에서 '상세 보기' -> 모달 내용 확인 -> Esc로 닫으면 '상세 보기' 버튼으로 초점이 돌아옴
4. 카메라 동의 후 '화상통화 설정 시작하기' -> '돌아가기'를 누르면 동의가 취소되고 체크박스로 초점 이동

## 11주차 개선: 웹 접근성과 포용적 인터페이스

### 접근성 개선 내용 (개선 전 → 개선 후)

**1. 키보드 초점 표시**
- 개선 전: 초점 테두리가 연한 하늘색이라 흰 배경과 거의 구분되지 않음 (대비 1.34:1). 링크와 선택 목록에는 초점 스타일이 없음
- 개선 후: 링크, 버튼, 입력칸, 선택 목록에 진한 파란색 3px 테두리 적용, 다크 테마에서는 노란색 테두리

**2. 다크 테마 글자 색 대비**
- 개선 전: 제목이 어두운 배경과 같은 계열 색이라 거의 보이지 않음. 카메라 동의 안내는 밝은 배경에 밝은 글자, 학습 소식 안내는 회색 카드에 회색 글자
- 개선 후: 제목은 연보라, 본문은 밝은 흰색으로 변경. 밝은 배경의 안내 문구는 어두운 글자로 고정

**3. 색상 외의 상태 구분**
- 개선 전: 학습 설정의 현재 단계가 글자 색으로만 구분됨. 비활성 버튼은 흰 글자에 회색 배경으로 색으로만 구분
- 개선 후: 현재 단계에 밑줄을 추가하고 `aria-current="step"`으로 화면 낭독기에도 알림. 비활성 버튼은 진한 글자와 점선 테두리로 구분
- 기존에 적용한 부분: 오류는 "오류:" 문구, 필수 항목은 '필수' 표시, 선택한 필터는 `✓` 표시, 현재 메뉴는 밑줄로 구분

**4. 이미지 대체 텍스트**
- 개선 전: `alt="영어 학습의 전체 과정과 주요 기능을 한눈에"`로 이미지의 실제 내용을 알 수 없음
- 개선 후: 학습자가 원어민과 화상통화하는 모습과 서비스 3단계(단어·문장 학습 -> 원어민 회화 -> 게임 복습), 이용 방법 5단계를 안내한다는 내용으로 작성

**5. 라벨과 버튼 이름**
- 개선 전: 학습 단어 수 슬라이더 값이 화면 낭독기에서 "0, 1, 2"로 읽힘. 버튼 이름이 '이전'만 있어 어디로 가는지 알기 어려움. 이름·이메일 입력칸과 안내 문구가 연결되어 있지 않음
- 개선 후: 슬라이더에 `aria-valuetext`로 "3개, 5개, 10개"를 읽어 주도록 변경. 버튼을 '이전 단계로'로 변경. 입력칸과 글자 수/안내 문구를 `aria-describedby`로 연결

**6. 키보드 조작과 이동 순서**
- 개선 전: 학습 설정에서 '다음' 버튼을 누르면 버튼이 숨겨지면서 초점이 사라져 Tab을 누르면 페이지 처음부터 다시 이동. 키보드 사용자는 매번 메뉴 7개를 지나가야 본문에 도착
- 개선 후: 단계가 바뀌면 새 단계 제목으로 초점 이동. 페이지 맨 앞에 '본문 바로가기' 링크 추가 (Tab을 처음 누르면 나타남). 모바일 메뉴가 열려 있을 때 Esc 키로 닫고 메뉴 버튼으로 초점을 되돌림

**7. 읽기 쉬운 구조와 오류 안내**
- 개선 전: 학습 설정 진행 단계가 `<p>` 안의 `<span>`으로 되어 있어 목록으로 인식되지 않음. 학습 소식 신청은 빈 값일 때 처음 안내와 같은 문구만 다시 보여 주고, @가 없는 주소도 신청됨
- 개선 후: 진행 단계를 순서 목록(`<ol>`)으로 변경. 학습 소식 신청에서 빈 값이나 @가 없는 주소는 "오류: 이메일 주소를 확인해 주세요. name@example.com 처럼 @가 들어간 주소를 입력한 뒤 신청해 주세요."라고 안내하고 `aria-invalid` 표시

### 키보드 확인 순서
1. 페이지를 열고 Tab -> '본문 바로가기' 표시 -> Enter로 본문 이동
2. Tab / Shift+Tab으로 메뉴, 탭, 입력칸, 버튼 사이를 이동하며 초점 테두리가 잘 보이는지 확인
3. 카메라 동의 체크박스에서 Space -> '화상통화 설정 시작하기'에서 Enter -> 안내 창에서 Enter
4. 닉네임 입력 후 Tab으로 '학습 조건 선택하기' 버튼에서 Enter -> 초점이 새 단계 제목으로 이동 / 슬라이더는 방향키로 조절
5. 학습 시작 후 답을 입력하고 Enter로 정답 확인, Tab으로 '다음 문제'까지 이동
6. 모바일 화면에서 '메뉴 열기' Enter -> Esc로 닫기 -> 초점이 메뉴 버튼으로 돌아옴

## 10주차 추가한 기능: 내비게이션 메뉴와 예약 내역 필터

### 추가/수정한 내용
- 주요 메뉴를 `nav > ul > li` 구조로 바꾸고, 스크롤해도 화면 위에 고정되도록 수정
- 현재 위치 메뉴를 색상과 밑줄(모바일은 왼쪽 막대와 배경)로 구분하고 `aria-current="page"` 적용
- 좁은 화면(768px 이하)에서는 '메뉴 열기/메뉴 닫기' 버튼으로 메뉴를 펼치고 접음
- 예약 폼 아래에 있던 예약 목록을 **'나의 예약 내역'** 영역(`#reservations`)으로 분리하고 수업 주제 필터 추가

### 메뉴별 목적지
| 메뉴 | 목적지 | 내용 |
| --- | --- | --- |
| 서비스 소개 | `#about` | 서비스 소개와 대표 이미지 |
| 학습 기능 | `#features` | 학습 기능 탭 |
| 이용 방법 | `#steps` | 서비스 이용 순서 |
| 화상통화 설정 | `#event-practice` | 카메라 동의, 학습 설정, 오늘의 단어 학습 시작 |
| 화상수업 예약 | `#reserve` | 원어민 화상수업 예약 폼 |
| 나의 예약 내역 | `#reservations` | 저장된 예약 목록과 주제 필터 |
| 학습 소식 받기 | `#subscribe` | 이메일 소식 신청 |

### 현재 위치 표시
- 메뉴를 누르면 주소 끝의 `#값`이 바뀌고, `hashchange` 이벤트에서 같은 `href`를 가진 메뉴에만 `aria-current="page"`를 넣고 나머지 메뉴에서는 지움 (`script.js`의 `updateCurrentMenu()`)
- 새로고침: 페이지를 열 때 `updateCurrentMenu()`를 한 번 실행해서 주소의 `#값`에 맞는 메뉴를 표시 (`#`이 없으면 '서비스 소개')
- 뒤로 가기 / 앞으로 가기: 주소의 `#값`이 바뀌면서 `hashchange`가 발생하므로 표시가 함께 바뀜

### 필터 기준
- 기준: 예약할 때 고른 **수업 주제**
- 필터: 전체 / 자유 대화 / 오늘 배운 단어 복습 / 상황별 회화
- 선택한 버튼은 색상과 함께 `✓` 표시가 붙고, `aria-pressed="true"`로 바뀜 (나머지는 `false`)
- 결과 수 안내: "전체 예약 3개를 보여 주고 있습니다." / "'상황별 회화' 수업 1개를 보여 주고 있습니다. (전체 3개)"
- 빈 결과 안내
  - 예약이 하나도 없을 때: "아직 예약한 수업이 없습니다. 메뉴의 '화상수업 예약'에서 첫 수업을 예약해 보세요."
  - 선택한 주제의 예약만 없을 때: "'오늘 배운 단어 복습' 주제로 예약한 수업이 없습니다. 다른 주제를 고르거나 '전체'를 눌러 보세요."

### 모바일 메뉴
- 768px 이하에서는 메뉴 목록을 숨기고 '메뉴 열기' 버튼을 표시
- 버튼을 누르면 메뉴가 펼쳐지고 버튼 문구가 '메뉴 닫기', `aria-expanded="true"`로 바뀜 (한 번 더 누르면 반대로)
- 메뉴에서 목적지를 누르면 해당 위치로 이동하고 메뉴가 닫힘 (`script.js`의 `setMenuOpen()`)
- 넓은 화면에서는 버튼을 숨기고 메뉴를 한 줄로 표시

### 확인 순서
1. 처음 열기 -> '서비스 소개' 메뉴가 현재 위치로 표시됨
2. 메뉴에서 '화상수업 예약' 클릭 -> 예약 폼으로 이동, '화상수업 예약' 메뉴만 현재 위치로 표시
3. 예약 전 '나의 예약 내역' 클릭 -> "전체 예약 0개", "아직 예약한 수업이 없습니다." 안내
4. 주제를 바꿔 가며 예약 2~3개 저장 (예: 자유 대화, 상황별 회화)
5. '나의 예약 내역'에서 필터 선택 -> 버튼 선택 표시(✓)와 목록, 결과 수가 함께 바뀜 / 예약이 없는 주제를 고르면 "해당 주제로 예약한 수업이 없습니다" 안내
6. 새로고침 -> 현재 메뉴 표시가 그대로 '나의 예약 내역' / 브라우저 뒤로 가기 -> '화상수업 예약'으로 돌아가고 메뉴 표시도 함께 바뀜
7. 모바일(360px)에서 '메뉴 열기' -> 메뉴 펼침, 버튼 문구 '메뉴 닫기' → 메뉴 선택 시 이동 후 메뉴 닫힘
8. 기존 기능 확인: 화상통화 설정 -> 학습 설정 → 오늘의 단어 학습, 화상수업 예약, 학습 소식 신청이 그대로 동작

## 9주차 추가한 기능: 원어민 화상수업 예약 폼

### 추가·수정한 내용
- 서비스의 주요 행동인 '원어민 화상통화'와 연결되는 **원어민 화상수업 예약 폼** 추가
- 상단 메뉴에 '화상수업 예약' 링크 추가
- 학습 설정의 **닉네임 입력칸 개선** (`#nickname-field`): `필수` 표시, 1자 이상 10자 이하 조건 도움말, 입력 중 글자 수(`0 / 10자`) 표시, 비어 있으면 오류 문구를 보여 주고 입력하면 바로 해제
- 학습 설정의 **문장 포함 조건부 입력 개선**: '문장도 함께 학습할게요'를 체크하면 문장 수 영역이 나타나고 라디오 버튼의 `disabled`가 해제되며, 체크를 풀면 영역이 숨겨지고 다시 `disabled` 처리됨
- 필수 항목은 `<span class="required">필수</span>`로 표시하고 입력칸에 `required`, `minlength`, `maxlength` 속성 추가
- 입력 항목: 예약자 이름(텍스트), 수업 날짜(날짜), 수업 시간(선택 목록), 수업 주제(라디오), 선생님께 전할 말(여러 줄 텍스트), 피드백 이메일 받기(체크박스)
- 모든 입력 요소에 label을 연결하고, 입력 조건 도움말을 `aria-describedby`로 연결
- 예약 내용은 브라우저 저장 기능(localStorage)에 저장하고 '나의 예약 내역'에 표시

### 입력 조건
| 항목 | 조건 | 오류 문구 예시 |
| --- | --- | --- |
| 닉네임 (학습 설정) | 필수, 1~10자 | "오류: 닉네임이 비어 있습니다. 1자 이상 10자 이하로 입력해 주세요." |
| 예약자 이름 | 필수, 2~10자 | "오류: 이름이 너무 짧습니다. 2자 이상 입력해 주세요." |
| 수업 날짜 | 필수, 오늘 이후 날짜 | "오류: 지난 날짜는 예약할 수 없습니다. 오늘 이후의 날짜를 선택해 주세요." |
| 수업 시간 | 필수 | "오류: 수업 시간을 선택해 주세요." |
| 선생님께 전할 말 | 필수, 10자 이상 (최대 200자) | "오류: 선생님께 전할 말을 10자 이상 적어 주세요. (5자 더 필요)" |
| 피드백 이메일 | 체크박스 선택 시에만 필수, @와 . 포함 | "오류: 이메일 형식이 아닙니다. name@example.com 처럼 입력해 주세요." |

### 구현 내용
- **조건부 입력**: '수업이 끝난 뒤 학습 피드백을 이메일로 받기'를 체크하면 이메일 입력 영역이 나타나고 `disabled`가 해제된다. 체크를 풀면 영역이 숨겨지고 `disabled` 처리되며 입력값과 오류도 지워진다.
- **입력 중 피드백**: 이름은 "3 / 10자", 전할 말은 "5 / 200자 (5자 더 필요)" -> "18 / 200자 (조건 충족)"처럼 글자 수와 조건 충족 여부를 문구로 표시한다.
- **오류 표시와 해제**: 오류가 난 칸은 빨간 테두리와 "오류:"로 시작하는 문구를 함께 보여 준다. 오류가 있는 칸은 입력할 때마다 다시 검사해서 올바르게 고치면 바로 오류가 사라진다.
- **제출 처리**: `form`의 `submit` 이벤트에서 `preventDefault()` 후 모든 항목을 검사한다.
  - 조건 미충족: 제출을 막고 "수정이 필요한 항목: 예약자 이름, 수업 시간"처럼 안내한 뒤 첫 번째 오류 칸으로 초점을 옮긴다.
  - 제출 중: "예약하는 중..." 문구를 표시하고 제출·다시 작성 버튼을 비활성화하여 중복 제출을 막는다. (`isReserving` 변수로 한 번 더 확인)
  - 성공: 1초 뒤 localStorage에 저장하고 완료 안내를 표시한 뒤 폼을 비운다.
  - 실패: 입력 내용은 그대로 두고 실패 안내를 표시하며, 버튼을 다시 활성화해 바로 다시 시도할 수 있다.
- **다시 작성**: 입력값과 함께 오류 문구, 글자 수 안내, 조건부 영역, 상태 문구, 버튼 상태가 모두 처음으로 돌아간다.

### 실패 처리 조건과 코드 위치
- `script.js`의 `saveReservation()` 함수
  1. **같은 날짜·같은 시간에 이미 예약이 있는 경우**: 저장하지 않고 "예약에 실패했습니다. ... 이미 예약된 시간입니다." 안내, 수업 시간 칸에 오류 표시 후 초점 이동
  2. **브라우저 저장 공간을 사용할 수 없는 경우**: `try...catch`로 잡아서 실패 안내 표시

### 확인 순서
1. 아무것도 입력하지 않고 '예약 신청하기' -> 제출이 막히고 수정할 항목 목록과 각 칸의 오류 문구 표시, 이름 칸에 초점
2. 이름에 '홍' 입력 -> "2자 이상 입력" 오류 / '홍길동'으로 수정 -> 오류 해제
3. 전할 말에 'hello' 입력 -> "5자 더 필요" / 10자 이상 입력 -> "조건 충족"(초록색)
4. 피드백 받기 체크 -> 이메일 칸 표시·입력 가능 / 'abc' 입력 후 제출 -> 이메일 형식 오류 / 체크 해제 -> 칸이 숨겨지고 disabled
5. 날짜·시간 선택 후 제출 -> "예약하는 중..." 표시, 버튼 비활성화 -> 1초 뒤 완료 안내와 예약 내역 추가
6. 같은 날짜·시간으로 한 번 더 예약 -> 실패 안내, 입력 내용 유지, 시간을 바꾸면 오류 해제 후 다시 신청 가능
7. 입력 도중 '다시 작성' -> 입력값, 오류 문구, 글자 수, 조건부 영역, 버튼 상태 모두 초기화

## 7주차 학습자의 흐름
1. 카메라 활용에 동의하고 '화상통화 설정 시작하기'를 누른다.
2. 안내 팝업에서 '동의하고 설정 시작하기'를 누른다.
3. 닉네임을 입력한다.
4. 학습 단어 수(3개/5개/10개)과 문장 포함 여부, 문장 수를 선택한다.
5. 입력한 내용을 확인하고 '설정 완료하기'를 누른다. 필요하면 '수정하기' 또는 '다시 설정하기'를 누른다.

## 새로 추가한 기능(중간시험 레포트): 오늘의 단어 학습

### 기능 설명
7주차 흐름의 끝인 설정 완료 화면에 '오늘의 단어 학습 시작하기' 버튼을 연결
앞에서 입력한 닉네임과 선택한 학습 단어 수, 문장 옵션에 맞춰 문제가 만들어지고 학습자는 한국어 뜻을 보고 영어 단어와 문장을 직접 입력하며 학습 진행

### 연결 지점과 설정값 반영
- 연결 지점: 설정 완료 화면 -> 오늘의 단어 학습 -> 결과 -> 설정 완료 화면
- 닉네임 -> 학습 화면 제목과 결과 문구에 표시
- 출제 단어 수 (3개, 5개, 10개, 단어 순서는 램덤)
- 문장 포함 / 문장 수 -> 단어 뒤에 선택한 개수만큼 문장 문제 추가

### 인터랙션 시나리오
1. 학습 시작
- 사용자 행동: 설정 완료 화면에서 '오늘의 단어 학습 시작하기'를 누른다.
- 반응: 설정 화면을 닫고 학습 화면을 연다. "학습 단어 수 5개 설정에 맞춰 단어 5개와 문장 2개를 준비했습니다."처럼 준비한 문제를 안내하고 입력창에 초점을 둔다.

2. 정답 확인
- 사용자 행동: 한국어 뜻을 보고 영어를 입력한 뒤 '정답 확인'을 누르거나 엔터를 누른다.
- 확인할 조건: 입력값이 비었는가? 한글이 섞였는가? 정답과 같은가? (대소문자, 앞뒤 공백, 문장부호 . , ? ! 는 구분하지 않음)
- 성공 반응: "정답입니다! 잘 입력했어요." 안내를 초록색으로 보여 주고 입력창을 잠근다.
- 오류 반응
  - 빈 값: "답이 비어 있습니다. 한국어 뜻에 맞는 영어를 입력한 뒤 '정답 확인'을 눌러 주세요." 입력창을 빨간 테두리로 표시하고 초점을 둔다.
  - 한글 입력: "한글이 입력되었습니다. 한/영 키를 눌러 영어로 바꾼 뒤 다시 입력해 주세요." (기회는 줄어들지 않음)
  - 오답: "정답이 아닙니다. 철자를 확인하고 다시 입력해 주세요. (남은 기회 2번)" 입력값은 지우지 않아 바로 고칠 수 있다.
  - 3번 모두 틀림: 정답을 알려 주고 틀린 문제로 기록한다.
- 다음 행동: '다음 문제' 버튼(마지막 문제에서는 '결과 보기')을 누른다.

3. 힌트 보기
- 사용자 행동: '힌트 보기'를 누른다.
- 반응: 단어는 첫 글자와 글자 수, 문장은 첫 단어와 단어 수를 보여 준다. 문제마다 한 번만 쓸 수 있고, 사용하면 버튼이 비활성화된다.

4. 건너뛰기
- 사용자 행동: '이 문제 건너뛰기'를 누른다.
- 반응: 정답을 보여 주고 틀린 문제로 기록한다. '다음 문제' 버튼으로 이어진다.

5. 학습 그만두기 (취소)
- 사용자 행동: '학습 그만두기'를 누른다.
- 반응: 바로 종료하지 않고 "학습을 그만둘까요?" 확인 창을 보여 준다.
  - '계속 학습하기': 입력하던 답, 본 힌트, 진행 상황을 그대로 유지하고 학습 화면으로 돌아간다.
  - '그만두고 돌아가기': 이번 학습 상태를 초기화하고 설정 완료 화면으로 돌아간다. 설정값은 유지된다.

6. 결과 확인
- 반응: "OO님은 7문제 중 5문제를 맞혔습니다. (힌트 사용 1번, 건너뛴 문제 1개)"처럼 결과를 보여 준다.
  - 틀린 문제가 있는 경우: '다시 볼 문제' 목록(뜻 -> 정답)과 '틀린 문제 N개만 다시 풀기' 버튼을 보여 준다.
  - 틀린 문제가 없는 경우 (결과 없음): 목록 대신 "틀린 문제가 없습니다. 모두 맞혔어요!" 안내를 보여 주고 다시 풀기 버튼을 숨긴다.
- 다음 행동: '틀린 문제만 다시 풀기', '처음부터 다시 풀기'(같은 설정, 새로 섞은 단어), '학습 설정으로 돌아가기' 중 선택한다.

7. 다시 설정하기
- 설정 완료 화면에서 '다시 설정하기'를 누르면 설정값과 함께 학습 상태(문제, 점수, 틀린 문제 목록)도 초기화된다.
